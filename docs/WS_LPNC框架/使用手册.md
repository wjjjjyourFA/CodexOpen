# WS_LPNC 使用手册

## 1. 适用范围

本手册说明 WS_LPNC 框架中四套已迁移流程的编译、安装、检查和
组合运行方式：

- `robot_dog_rebuild`：FAST-LIO、手动回环会话导出、状态监控；
- `robot_dog_localization`：加载先验 PCD 地图，通过 RViz 初值实现有图定位；
- `robot_plan_expv2`：ROG-Map、地形分析、世界规划、本地规划和地形探索；
- `robot_plan_path`：复用前四个组件，以文件/RViz 航点发布器取代地形探索。

这些流程统一由顶层 CMake/Ninja 构建。`ros1/src` 只保存 ROS1 接口
适配源码，不再使用迁移时的 `roslaunch` bringup 包作为入口。

## 2. 编译和安装

首先准备 ROS1 Noetic 环境，然后在仓库根目录执行：

```bash
source /opt/ros/noetic/setup.bash
mkdir -p build
cd build
cmake -G Ninja .. \
  -DBUILD_ROS1=ON \
  -DBUILD_ROS2=OFF \
  -DBUILD_TESTING=OFF \
  -DCMAKE_INSTALL_PREFIX=/workspaces/CodexOpen-main/install
ninja -j2
ninja install
```

运行时必须使用 `install` 中的产物，而不是直接依赖 `build` 中的
临时文件。安装后可先做静态完整性检查：

```bash
install/scripts/robot_dog_rebuild.sh --check
install/scripts/robot_dog_localization.sh --check
install/scripts/robot_plan_expv2.sh --check
install/scripts/robot_plan_path.sh --check
```

`--check` 不启动 ROS master 和算法进程，只检查已启用组件的可执行文件、
参数和资源。

## 3. robot_dog_rebuild

启动 Livox 驱动后执行：

```bash
install/scripts/robot_dog_rebuild.sh
```

无桌面环境建议关闭 RViz，并使用终端状态监控：

```bash
ROBOT_DOG_RVIZ=false \
ROBOT_DOG_STATUS_MODE=terminal \
install/scripts/robot_dog_rebuild.sh
```

常用覆盖项：

| 环境变量 | 用途 |
| --- | --- |
| `ROBOT_DOG_FAST_LIO_CONFIG` | FAST-LIO 算法参数文件 |
| `ROBOT_DOG_FAST_LIO_INTERFACE` | FAST-LIO topic/frame 接口文件 |
| `ROBOT_DOG_EXPORTER_CONFIG` | 会话导出器运行参数 |
| `ROBOT_DOG_EXPORTER_INTERFACE` | 会话导出器话题和同步参数 |
| `ROBOT_DOG_SESSION_ROOT` | 当次关键帧、TUM 位姿和 G2O 位姿图输出目录 |
| `ROBOT_DOG_LOG_DIR` | 当次运行日志目录 |

默认接口是 `/livox/lidar` 和 `/imu/data` 输入，输出
`/lio/odom`、`/state_estimation`、`/lio/path` 和 `/registered_scan`。
`/lio/path` 直接使用 `map` frame，动态 TF 保持 `map -> sensor`。

## 4. robot_dog_localization 有图定位

该流程先启动 RViz，再启动 `localization_robot_ros1`。定位节点加载随模块安装的
先验 PCD，并在启动时发布一次 `/world_state/cloud_map`；RViz 预先订阅后可以稳定
显示地图，并通过 `2D Pose Estimate` 向 `/initialpose` 提供初始位姿：

```bash
install/scripts/robot_dog_localization.sh --check
install/scripts/robot_dog_localization.sh
```

默认算法参数保持旧 `Localization.yaml` 的数值，当前 `lidar_type: 1` 使用
`/livox/lidar` 和 `/imu/data`。初始化完成后输出 `/lio/odom`、
`/state_estimation`、`/lio/path`、`/registered_scan`，并发布动态
`map -> sensor` TF。与框架内 FAST-LIO 一致，`/lio/path` 的 header 和 pose
均直接使用 `map` frame。

RViz 是可选辅助进程，不是流程存活条件。关闭 RViz 后定位节点继续运行；按总控
脚本所在终端的 `Ctrl-C` 才会停止整套流程。若已经提前打开了外部 RViz，也可以：

```bash
ROBOT_DOG_LOCALIZATION_RVIZ=false \
  install/scripts/robot_dog_localization.sh
```

此时应确保外部 RViz 已订阅地图话题，否则会错过只发布一次的先验地图。常用覆盖项：

| 环境变量 | 用途 |
| --- | --- |
| `ROBOT_DOG_LOCALIZATION_CONFIG_DIR` | 整体替换定位配置目录 |
| `ROBOT_DOG_LOCALIZATION_RUNTIME` | 算法参数 YAML |
| `ROBOT_DOG_LOCALIZATION_INTERFACE` | topic/frame 接口 YAML |
| `ROBOT_DOG_LOCALIZATION_MAP` | 替换先验 PCD 地图 |
| `ROBOT_DOG_LOCALIZATION_RVIZ` | 是否由总控脚本启动 RViz |
| `ROBOT_DOG_LOCALIZATION_RVIZ_CONFIG` | 替换 RViz 配置 |
| `ROBOT_DOG_LOCALIZATION_RVIZ_LEAD_TIME` | RViz 相对定位节点的提前启动秒数 |
| `ROBOT_DOG_LOCALIZATION_LOG_DIR` | 当次运行日志目录 |

## 5. robot_plan_expv2 默认完整组合

```bash
install/scripts/robot_plan_expv2.sh
```

这是为方便复现原实验流程提供的默认组合，不表示五个程序在架构上
是一个模块。无桌面环境使用：

```bash
ROBOT_PLAN_LOCAL_RVIZ=false \
ROBOT_PLAN_ROG_MAP_RVIZ=false \
install/scripts/robot_plan_expv2.sh
```

## 6. 自由组合组件

两个规划流程共用 `robot_plan_stack.sh` 组合器，薄入口只设置各自默认值：

| 组件 | `robot_plan_expv2` | `robot_plan_path` |
| --- | --- | --- |
| ROG-Map | 启用 | 启用 |
| 地形分析 | 启用 | 启用 |
| 世界规划 | 启用 | 启用 |
| 本地规划 | 启用 | 启用 |
| 地形航点探索 | 启用 | 禁用 |
| 文件/RViz 航点发布 | 禁用 | 启用 |

每个组件都有独立开关：

| 开关 | 组件 | 所属域 |
| --- | --- | --- |
| `ROBOT_PLAN_ENABLE_ROG_MAP` | ROG-Map | 感知 |
| `ROBOT_PLAN_ENABLE_TERRAIN_ANALYSIS` | 地形分析 | 感知 |
| `ROBOT_PLAN_ENABLE_WORLD_PLANNER` | 世界规划 | 规划 |
| `ROBOT_PLAN_ENABLE_LOCAL_PLANNER` | 本地规划 | 规划 |
| `ROBOT_PLAN_ENABLE_TERRAIN_EXPLORER` | 地形航点探索 | 规划 |
| `ROBOT_PLAN_ENABLE_WAYPOINT_PUBLISHER` | 文件/RViz 航点发布 | 规划 |
| `ROBOT_PLAN_ENABLE_STATIC_TF` | `sensor -> vehicle` 静态 TF | 流程编排 |

`ROBOT_PLAN_ENABLE_STATIC_TF` 未显式设置时跟随本地规划开关。
地形探索和航点发布器都会发布 `/way_point` 与 `/isgoal_vaild`，组合器禁止
两者同时启动。

## 7. robot_plan_path

默认启动原 `robot_plan_path.sh` 对应的六个进程/组件：

```bash
install/scripts/robot_plan_path.sh
```

无桌面环境：

```bash
ROBOT_PLAN_LOCAL_RVIZ=false \
ROBOT_PLAN_ROG_MAP_RVIZ=false \
install/scripts/robot_plan_path.sh
```

航点发布器读取 `WaypointPublisher/data/waypoint.txt` 和 `boundary.txt`，并发布
`/way_point`、`/way_point_show`、`/speed`、`/navigation_boundary` 和
`/isgoal_vaild`。它还接收 RViz `/move_base_simple/goal` 追加的航点。

为保持旧流程语义，world planner 在该流程中读取同一份 waypoint 文件用于边界
计算；`robot_plan_expv2` 仍读取 `WorldPlanner/data/waypoint.txt`。

## 8. 裁剪组合示例

只启动感知部分：

```bash
ROBOT_PLAN_ENABLE_WORLD_PLANNER=false \
ROBOT_PLAN_ENABLE_LOCAL_PLANNER=false \
ROBOT_PLAN_ENABLE_TERRAIN_EXPLORER=false \
ROBOT_PLAN_ENABLE_STATIC_TF=false \
ROBOT_PLAN_LOCAL_RVIZ=false \
install/scripts/robot_plan_expv2.sh
```

只启动规划部分：

```bash
ROBOT_PLAN_ENABLE_ROG_MAP=false \
ROBOT_PLAN_ENABLE_TERRAIN_ANALYSIS=false \
ROBOT_PLAN_ROG_MAP_RVIZ=false \
install/scripts/robot_plan_expv2.sh
```

此时必须由外部节点提供规划程序需要的 `/terrain_map`、
`/state_estimation` 和 `/registered_scan` 等输入。组合开关只决定启动哪些
程序，不伪造缺失的数据。

单独启动某个程序时，也可直接调用其安装产物。例如：

```bash
install/bin/modules/perception/terrain_analysis/terrain_analysis_ros1 \
  install/bin/config/TerrainAnalysis/TerrainAnalysis.yaml \
  install/bin/config/TerrainAnalysis/Interface.yaml
```

## 9. 替换单个模块的配置

每个模块的配置目录可独立替换：

```bash
ROBOT_PLAN_ROG_MAP_CONFIG_DIR=/path/to/RogMap \
ROBOT_PLAN_TERRAIN_CONFIG_DIR=/path/to/TerrainAnalysis \
install/scripts/robot_plan_expv2.sh
```

其余目录覆盖变量为 `ROBOT_PLAN_WORLD_CONFIG_DIR`、
`ROBOT_PLAN_LOCAL_CONFIG_DIR`、`ROBOT_PLAN_EXPLORER_CONFIG_DIR` 和
`ROBOT_PLAN_WAYPOINT_CONFIG_DIR`。`ROBOT_PLAN_WORLD_WAYPOINT_FILE` 可单独覆盖 world planner
用于计算边界的航点文件。每个目录内：

- `Interface.yaml` 只保存 topic、frame、同步策略和外部 I/O；
- `<Module>.yaml` 保存原算法/运行参数；
- `paths/`、`data/` 和 `rviz/` 是当前模块自己的只读资源。

## 10. 日志和停止

总控脚本会复用已有 ROS master；若不存在则自行启动。每个子进程的
标准输出和 ROS 日志都写入当次日志目录。按 `Ctrl-C` 时，脚本会按逆序
停止自己启动的进程；外部已存在的 ROS master 不会被关闭。

默认日志位置：

```text
install/log/robot_dog_rebuild/<timestamp>/
install/log/robot_dog_localization/<timestamp>/
install/log/robot_plan_expv2/<timestamp>/
install/log/robot_plan_path/<timestamp>/
```

## 11. 常见问题

1. 提示可执行文件不存在：确认已使用 `BUILD_ROS1=ON` 重新配置，并执行
   `ninja install`。
2. 单独启动节点但无输出：检查该节点的 `Interface.yaml` 所声明的上游
   topic 是否存在。
3. RViz 报 TF 不连通：定位主树是 `map -> sensor -> vehicle`。ROG-Map 的
   历史 `world/body/drone` frame 仍由其原有实现产生，框架层未虚构
   `map -> world` 外参。
4. 请不要再运行旧 `robot_plan_expv2.launch`、`robot_dog_path.launch` 或
   `robot_dog_rebuild.launch`；迁移流程的唯一组装入口是 `install/scripts` 中的
   脚本。
5. 有图定位的 RViz 中没有地图：确认 RViz 在定位节点之前启动；最简单的恢复方式
   是停止总控脚本后重新运行。关闭 RViz 本身不会停止仍在运行的定位节点。
