# WS_LPNC 框架结构说明

## 1. 核心原则

WS_LPNC 将一个可运行模块拆成三层，依赖方向只能由外向内：

```text
script/ 运行编排
   │ 启动独立进程、管理日志和生命周期
   v
ros1/src/ 通信适配
   │ 参数装载、ROS 消息转换、topic/service/TF/timer
   v
modules/ 或 tools/ 纯核心
     算法、状态机和通信框架无关的数据结构
```

核心层不得包含 ROS/ROS2/DDS 头文件、NodeHandle、publisher/subscriber、
TF、ROS 时钟或 ROS 日志宏。需要当前时间的算法由适配层显式传入时间戳；
需要地图、路径库或输出目录的算法由进程入口显式传入路径。PCL、Eigen、
OpenCV 等算法库可以由核心使用，但其对象不能承担 ROS 通信职责。

ROS1 适配层只负责边界转换，不修改规划、建图或定位公式。多节点组合只放在
`script/`，不再用某个历史 launch 包充当核心模块。

适配源码由模块自己的 `CMakeLists.txt` 在 `BUILD_ROS1=ON` 时组合，不在
`ros1/src` 另建第二套构建主体。

## 3. 模块内部标准

标准 C++ 模块结构为：

```text
modules/<domain>/<module>/
├── CMakeLists.txt
├── <core headers and sources>
└── config/runtime/
    ├── <Module>.yaml       算法和模块运行参数
    ├── Interface.yaml      topic、service、frame、队列、同步和外部 I/O
    └── data|paths|rviz/    模块自有只读资源（按需）

ros1/src/<domain>/<module>/
├── include/<module>_ros1/ros1_convert.h
└── src/
    ├── ros1_convert.cpp
    └── run_<module>_ros1.cpp
```

FAST-LIO 的接口文件也统一命名为 `Interface.yaml`。状态监控是 Python 模块，
保留等价的 `RobotStatusMonitor.ini` 与 `Interface.ini`；其核心文件
`robot_status_monitor_core.py` 与 ROS 节点脚本仍位于对应两层。

每个 C++ 模块至少产生一个纯核心静态库。只有 `BUILD_ROS1=ON` 时才查找
catkin 并产生 `<module>_ros1` 可执行文件，因此 `BUILD_ROS1=OFF` 的核心构建
命令不需要 ROS include 或 link 路径。

## 4. 纯核心入口

| 模块 | 纯核心入口 | 主要纯输入/输出 |
| --- | --- | --- |
| FAST-LIO | `FastLioPipeline` | Livox 点数组、IMU 数据、位姿/速度/注册点云 |
| 先验地图定位 | `PriorMapLocalization` | 点云、IMU、外部初值、位姿/速度/注册点云 |
| ROG-Map | `rog_map::ROGMap` | PCL 点云、`rog_map::Pose`、占据/ESDF 可视化数据 |
| 地形分析 | `TerrainAnalysis` | PCL 点云、公共 Pose、地形点云 |
| 世界规划 | `WorldPlanner` | 公共 Pose、PCL 地形、公共 Path/OccupancyGrid |
| 本地规划 | `LocalPlanner` | 公共 Path/Pose/Polygon/Twist 与 PCL 点云 |
| 地形航点探索 | `TerrainWaypointExplorer` | PCL 点云、公共 Pose、目标和调试点云 |
| 航点发布 | `WaypointPublisher` | 公共 Pose、航点/边界/速度状态 |
| 会话导出 | `SessionExporter` | Eigen 位姿、PCL 点云、关键帧写出结果 |
| 状态监控 | `RobotStatusMonitorCore` | 标量状态和显式单调时钟、状态快照 |

核心方法不接收 ROS 消息智能指针。消息回调先在 `ros1_convert` 中逐字段转换，
再调用 `Set*`、`Push*`、`Process`、`Step` 或 `Plan`。核心输出也先使用公共
结构，再由适配层构造 ROS 消息。

## 5. 公共消息定义

跨规划模块复用 `jojo::common_struct`，不复制 ROS 消息类：

| 类型 | 关键字段 | 时间单位 |
| --- | --- | --- |
| `Header` | `timestamp`、`seq`、`frame_id` | `timestamp` 为纳秒 |
| `Quaternion` | `x`、`y`、`z`、`w` | 单位四元数默认值 `(0,0,0,1)` |
| `Pose` | `position`、`orientation` | 与 `geometry_msgs/Pose` 逐字段对应 |
| `PoseStamped` | `header`、`recv_timestamp`、`pose` | 两个时间均为纳秒 |
| `Odometry` | header、child frame、pose、速度、两组 6×6 协方差 | 纳秒 |
| `Path` | `header`、`poses` | 纳秒 |
| `OccupancyGrid` | header、地图元数据、`int8` 栅格数据 | 纳秒 |
| `Twist` | 三维线速度和角速度 | 不含隐式时间 |
| `PolygonStamped` | header、`Vector3f` 点数组 | 纳秒 |

定位算法内部保留适合高频计算的 `double` 秒时间和 Eigen/PCL 状态；ROS 适配层
在边界处完成秒/纳秒转换。标准雷达点布局使用 `rs_lidar`、
`velodyne_lidar` 命名，不在核心中伪装成 ROS 类型。

## 6. 参数和资源归属

配置归属以“谁解释该值”为准：

- 分辨率、阈值、增益、滤波，以及算法内部的规划/控制频率属于运行参数；
- topic、service、frame、队列、latch、同步窗口、消息字段换算和适配循环频率
  属于 `Interface.yaml`；
- 输入/输出目录属于接口外部 I/O，路径库、先验 PCD 和 RViz 文件作为模块资源；
- 脚本只选择配置文件或资源的绝对路径，不把算法参数重新定义一遍；
- 不使用流程级 `Interface.yaml` 绑定多个模块。

运行入口依次接收 runtime、Interface，再接收本模块需要的资源路径。例如本地
规划额外接收 paths 目录，先验定位额外接收 PCD 和日志目录，航点发布器额外
接收 waypoint/boundary 文件。资源路径由入口写入适配参数，不写入核心源码。

ROG-Map 的 `safe_margin` 已作为核心配置显式初始化；历史配置中没有实现读取路径
的 `block_inf_pt`、`kd_tree_en`、`blind_filter_en` 和 `blind_filter_dis` 已删除，
避免形成无效参数。FAST-LIO 和规划模块的队列及适配循环频率由各自 Interface
文件声明；状态监控的订阅队列位于 `Interface.ini`，展示刷新率属于运行行为，
保留在 `RobotStatusMonitor.ini`。

## 7. ROS1 适配层职责

ROS1 适配层只做以下工作：

1. 创建 node、subscriber、publisher、service、timer 和 TF broadcaster；
2. 装载 runtime 与 Interface 配置并验证接口值；
3. 将 ROS 消息逐字段转换成公共结构、PCL/Eigen 数据或纯标量；
4. 把 ROS 时间显式传入核心；
5. 将核心结果转换成 ROS 消息并发布；
6. 记录 ROS 侧诊断日志。

`ros1/src/common/codexopen_ros1_yaml_param_loader` 只在适配目标中链接。
先验定位的 Livox 和旧 `self_state` 兼容消息头也只位于该模块的 ROS1 适配目录。
ROG-Map 动态配置类型使用模块命名 `rog_map_ros1::VizConfig`，不依赖历史流程名。

## 8. 默认消息链

```text
/registered_scan + /state_estimation
       │
       ├──> ROG-Map ──> /rm_node/rog_map/occ
       │                         │
       │                         v
       │                  terrain analysis ──> /terrain_map
       │                                           │
       │                                           ├──> world planner
       │                                           │          │
       └──> terrain waypoint exploration 或 waypoint publisher
                                                   │ /way_point
                                                   │          v
                                                   └──> local planner
                                                             │
                                                   /path + /cmd_vel_corrected
```

定位源有两种可替换实现：

```text
Livox + IMU ──> FAST-LIO ───────────────┐
                                        ├──> /state_estimation
先验 PCD + Livox + IMU + /initialpose ──┘    /registered_scan
                                             /lio/odom + /lio/path
```

FAST-LIO 和先验定位会发布同名主定位接口，不能同时作为同一 ROS master 的
主定位源。先验地图 `/world_state/cloud_map` 为 latched publisher，后启动的
RViz 也可收到地图。

## 9. TF 所有权

默认 TF 所有权如下：

- FAST-LIO 或先验定位发布动态 `map -> sensor`；
- 规划组合器按本地规划 Interface 发布静态 `sensor -> vehicle`；
- ROG-Map 消费 `/state_estimation`，默认 `broadcast_tf: false`，不重复发布
  `map -> sensor`；如独立部署确有需要，可在其 Interface 中显式启用；
- `/lio/path` 的 header 和每个 pose 使用 `map`；
- `/lio/odom` 保留兼容的 `world` frame；
- ROG-Map、地形、世界规划和探索的默认输出使用 `map`，本地规划输出使用
  `vehicle`。

未经标定不得在脚本层虚构额外 TF。

## 10. 运行编排

`robot_plan_stack.sh` 是规划组件的唯一组合器。`robot_plan_expv2.sh` 默认选择
地形航点探索，`robot_plan_path.sh` 默认选择文件/RViz 航点发布器；二者不包含
算法代码。探索器和航点发布器都拥有 `/way_point` 与 `/isgoal_vaild`，组合器
禁止同时启用。

`runtime_common.sh` 统一负责安装根目录解析、ROS 环境、ROS master、日志目录、
required/optional 进程和逆序清理。RViz 是 optional，关闭 RViz 不停止算法进程。

## 12. 准入和验证规则

新增或修改启动链模块必须同时满足：

1. 纯核心可在 `BUILD_ROS1=OFF` 下独立编译；
2. 核心源码扫描不到 ROS/ROS2 消息、节点、TF 或日志 API；
3. runtime/Interface 所有叶子参数都存在实际读取点，不能保留假配置；
4. topic、service、frame、队列、同步和适配频率只放 Interface；
5. 输入输出使用公共结构或明确的纯数据类型，转换集中在 `ros1_convert`；
6. ROS1 独立目标、全核心构建和 `cmake --install` 均成功；
7. 所有入口脚本通过 `bash -n` 与 `--check`；
8. 至少验证一种裁剪组合，并在真实传感器接入前明确说明硬件验证边界。

本轮拆分的逐模块实现和兼容约定见
[ROS接口与核心拆分说明](ROS接口与核心拆分说明.md)。
